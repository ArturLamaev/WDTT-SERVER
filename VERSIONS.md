# Версии и происхождение

Дата заморозки: 2026-09-22. Форк собран как монолит: обе части лежат в этом репозитории
и устанавливаются **только из локальных источников** (без загрузки оригиналов с GitHub).

## Версионирование

**Любое изменение кода требует бампа версии:**

- багфиксы → патч (`+0.0.1`), например `1.0.0 → 1.0.1`;
- новый функционал/фича → минор (`+0.1`), например `1.0.0 → 1.1.0`;
- мажорная обнова → мажор (`+1.0`), например `1.0.0 → 2.0.0`.

## 1.18.1

Починка выбора режима и виснущего сноса. Выбор «2» умирал в update-ветке

## 1.15.0

## 1.14.0

Telegram-бот контроллера (`fleet/bot.py`, команда `fleet bot`): те же

## 1.13.0

Fleet-контроллер, шаг 1 (ядро + CLI, без веба): новый пакет
`panel/wdtt_panel/fleet/` — управление несколькими нодами с домашнего
сервера. Ноды не меняются: контроллер — обычный HTTP-клиент к их `api/v1`
(логин по паролю → Bearer, дальше токен; при 401 один авто-ре-логин).

- `models.py` — нода `url + base_path + логин/пароль/токен`, нормализация
  полного URL (можно вбить вместе с секретным путём);
- `store.py` — реестр нод в JSON `0600` (`$WDTT_FLEET_STORE` или
  `~/.wdtt-fleet/nodes.json`);
- `client.py` — клиент одной ноды на stdlib (urllib, без зависимостей),
  GET для `info/overview/users`, POST для остального;
- `fanout.py` — параллельный прогон операции по нодам, частичный успех —
  норма (`{total, ok, fail, errors}` + итог по каждой ноде);
- `cli.py` (`python -m wdtt_panel.fleet`): `add/remove/list`,
  `status`, `keys` (ключи со всех нод), `create`, `delete` (`--node` или
  все; удаление со всех — только с `--everywhere`), `--json` для
  будущего бота/API.

Починка сохранения Telegram-бота («Внутренняя ошибка: [Errno 30]

## 1.9.1

Починка автооткрытия портов на старых системах (Astra Linux / Debian 9):

- старый ufw 0.35 не знает ключевое слово `comment` — `ufw allow ... comment`
  молча падал (`|| true` съедал ошибку), поэтому 9999/tcp и 80/tcp оставались
  закрыты, а Let's Encrypt не выпускался. Добавлен хелпер `ufw_allow()`:
  пробует с комментарием, при неудаче — без него, в крайнем случае пишет WARN
  в лог вместо тишины;
- порты ядра (56000/udp+tcp, 56001/udp, admin/SSH) раньше писались только
  в raw-iptables, чего при активном ufw недостаточно. `deploy.sh` теперь
  при активном ufw регистрирует их и там (`ufw_allow_port`, с тем же
  fallback без `comment`).

| `profile_api.go`  | `max_devices` в профиле больше не подменяется `1` при `<= 0` (отдаётся честно, `0` = безлимит) |

| Файл | Изменение |

### Установщик (`panel/install.sh`)

- добавлен режим локального ядра `WDTT_SOURCE_DIR` (по умолчанию `src/proxy-turn-vk-android-1.4.3`):
  сборка идёт **из локального форка**, GitHub-качалка используется только как fallback;
- при установке форк ядра копируется в `/opt/wdtt-panel/src`, чтобы последующие
  обновления из `/opt` тоже не обращались к GitHub.
