# Версии и происхождение

Дата заморозки: 2026-09-22. Форк собран как монолит: обе части лежат в этом репозитории
и устанавливаются **только из локальных источников** (без загрузки оригиналов с GitHub).

## Версионирование

**Любое изменение кода требует бампа версии:**

- багфиксы → патч (`+0.0.1`), например `1.0.0 → 1.0.1`;
- новый функционал/фича → минор (`+0.1`), например `1.0.0 → 1.1.0`;
- мажорная обнова → мажор (`+1.0`), например `1.0.0 → 2.0.0`.

## 1.3.0

Возвращена кнопка обновления панели, но на новом принципе (git pull → установка
с сохранением конфига → полный перезапуск):

- в раздел «Система» возвращён блок «PANEL UPDATE» с текущей/доступной версией,
  кнопками «Проверить обновления» и «Обновить панель»;
- проверка и обновление идут через обёртку `/usr/local/sbin/wdtt-panel-self-update`,
  которая запускается вне systemd-песочницы панели (через `systemd-run`), поэтому
  `git`, запись в `/etc`, `/opt`, `/usr` и перезапуск служб ей доступны;
- проверка (`check`) делает `git fetch` в каталоге репозитория и пишет доступную
  версию в `/var/lib/wdtt-panel-private/self-update-status.json`;
- обновление (`update`) выполняет `git pull`, затем `install.sh update`
  (конфиг и данные сохраняются) и полный перезапуск панели, ядра WDTT и демонов;
- каталог репозитория запоминается при установке/обновлении в
  `/etc/wdtt-panel/source.conf` (`WDTT_REPO_DIR`); если репозиторий недоступен,
  панель показывает понятную ошибку;
- добавлены роуты `panel/version`, `panel/check`, `panel/update`, функции
  `panel_version()`, `schedule_panel_check()`, `start_panel_update()` и команда
  `install.sh restart` для перезапуска служб.

## 1.2.0

Установка поверх работающей панели теперь предлагает обновление:

- `sudo ./install.sh` при наличии установленной панели печатает текущую и
  целевую версии и спрашивает, обновить ли её (по умолчанию — да);
- при согласии запускается путь обновления: конфиг и данные сохраняются,
  панель переводится на новую версию без потери пароля, URL-пути и сертификатов;
- перед миграцией `panel/install.sh update` создаёт снимок `config.json` в
  `/var/lib/wdtt-panel-private/config-backups/` (хранятся 20 последних) и
  снимок базы WDTT;
- конфиг переносится на новую версию: недостающие поля досыпаются значениями
  по умолчанию, порты нормализуются, поле `version` обновляется;
- `--force-clean` по-прежнему сносит установку и ставит начисто,
  `--non-interactive` обновляет панель без вопросов.

## 1.1.1

Удалён апстрим-механизм обновления панели из веб-интерфейса:

- из раздела «Система» убран блок «PANEL UPDATE / Версия панели» с кнопкой
  «Обновить панель», проверкой версии на GitHub и запуском самообновления;
- удалены роуты `panel/version` / `panel/update`, функции `panel_version()` и
  `start_panel_update()` в `admin.py`, а также `PANEL_VERSION_URL` и
  `PANEL_UPDATE_COMMAND`;
- установщик больше не создаёт wrapper `/usr/local/sbin/wdtt-panel-update` и не
  ставит `panel/update.sh` (файл удалён): раньше он скачивал апстрим
  `bootstrap.sh` с GitHub и подменял форк оригиналом;
- обновление выполняется вручную из локального форка:
  `sudo ./install.sh update` (из корня) или `sudo bash /opt/wdtt-panel/install.sh update`.

## 1.1.0

Авто-очистка диска:

- новый фон-таймер `wdtt-panel-autoclean.timer` проверяет диск каждые 30 минут;
- при заполнении диска выше порога (по умолчанию 90%) панель автоматически обрезает
  известные журналы, чистит systemd journal, кэш пакетов и сбрасывает failed-units;
- старые резервные копии удаляются агрессивно: панель — 20, пользователи — 20
  (лимиты настраиваются);
- настройки хранятся в `/var/lib/wdtt-panel-private/auto-clean.json` и управляются из
  раздела «Авто-очистка диска»; есть кнопка немедленной проверки и очистки.

## 1.0.0

Первый релиз под новым версионированием. Что вошло в форк к этому моменту:

- панель всегда работает от root и вызывает root-хелпер напрямую: юнит задаёт
  `RestrictAddressFamilies=`/`LockPersonality=`, а systemd для них принудительно
  включает `NoNewPrivileges=yes`, из-за чего sudo не может повысить права;
- устройства привязываются к ключу пользователя через `device_ids`, а не к «Администратору»;
- основной акцент панели сменён с зелёного на красный (индикаторы `ok` — зелёные);
- VK-хеши из `userdata/vk-hash.txt` автоматически импортируются в библиотеку панели при первой установке.

## Что изменено в форке

### Ядро (`src/proxy-turn-vk-android-1.4.3/server/`)

| Файл | Изменение |
|------|-----------|
| `database_bot.go` | `maxGeneratedPasswords` поднят **10 → 10000**; `canConnectAndBind()` теперь трактует `max_devices <= 0` как *без ограничения*; в Telegram-боте (`/new`) и `/list` лимит устройств по умолчанию **1 → 10000**, в `/list` для безлимита показывается `∞` |
| `admin_api.go`    | при создании/обновлении ключа `max_devices` по умолчанию **1 → 10000**, валидация принимает `0` = безлимит |
| `profile_api.go`  | `max_devices` в профиле больше не подменяется `1` при `<= 0` (отдаётся честно, `0` = безлимит) |

### Панель (`panel/wdtt_panel/`)

| Файл | Изменение |
|------|-----------|
| `core.py` | `MAX_USERS` — лимит пользователей/ключей **10 → 10000**; добавлен `DEFAULT_MAX_DEVICES = 10000` |
| `admin.py` | новые пользователи (создание и массовое) получают `max_devices = DEFAULT_MAX_DEVICES` |
| `static/app.js`, `templates/index.html` | счётчики «N / 10000», лимит диалогов берётся из API, массовое создание до 10000 |

### Установщик (`panel/install.sh`)

- добавлен режим локального ядра `WDTT_SOURCE_DIR` (по умолчанию `src/proxy-turn-vk-android-1.4.3`):
  сборка идёт **из локального форка**, GitHub-качалка используется только как fallback;
- при установке форк ядра копируется в `/opt/wdtt-panel/src`, чтобы последующие
  обновления из `/opt` тоже не обращались к GitHub.

## Как проверить, что лимиты сняты

```bash
grep maxGeneratedPasswords /opt/wdtt-panel/src/proxy-turn-vk-android-1.4.3/server/database_bot.go
# maxGeneratedPasswords = 10000
grep MAX_USERS /opt/wdtt-panel/wdtt_panel/core.py
# MAX_USERS = 10000
```

На работающем сервере: команда `/list` в Telegram-боте покажет «Активно: N/10000»,
а панель в разделе Пользователи — счётчик «N / 10000».
