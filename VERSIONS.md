# Версии и происхождение

Дата заморозки: 2026-09-22. Форк собран как монолит: обе части лежат в этом репозитории
и устанавливаются **только из локальных источников** (без загрузки оригиналов с GitHub).

## Версионирование

**Любое изменение кода требует бампа версии:**

- багфиксы → патч (`+0.0.1`), например `1.0.0 → 1.0.1`;
- новый функционал/фича → минор (`+0.1`), например `1.0.0 → 1.1.0`;
- мажорная обнова → мажор (`+1.0`), например `1.0.0 → 2.0.0`.

## 1.9.5

Починка маршрутизации WDTT → Xray/WARP (upstream lebrit/wdtt-control-panel#3):

- ядро выдаёт клиентам адреса из всей `/16` (`getNextIP`: `10.66.0.1` →
  `10.66.255.254`, `wgServerCIDR = 10.66.66.1/16`), а панель по умолчанию
  резала TPROXY-правилом `-s 10.66.66.0/24` (~0.4% пула). Первые пользователи
  получают `10.66.0.x` и никогда не попадали в Xray — статус выглядел
  активным, а трафик не шёл;
- дефолты шлюза и каскада теперь `10.66.0.0/16` (как NAT `10.66.0.0/16`
  в `deploy.sh`): `default_xray_settings`, `default_xray_cascade_settings`,
  веб-форма и JS-фолбэки;
- миграция существующих установок: сохранённые `10.66.66.0/24` (старый
  дефолт) и `10.66.0.0/24` (воркэраунд из issue) при загрузке раскрываются
  до `10.66.0.0/16`. Кастомные подсети не трогаем.

## 1.9.4

Полный тейкдаун действительно сносит и ядро WDTT:

- корневой `install.sh uninstall` и `--force-clean` теперь удаляют ядро
  штатным `deploy.sh uninstall` (сервис, интерфейс, NAT/firewall, sysctl),
  а не только файлами — раньше оставались интерфейс, iptables-правила
  и `99-wdtt.conf`, а в логе висело «WDTT не затрагивается»;
- ручные `rm` остались как fallback для остатков и данных (после бэкапа);
- в закрываемые при сносе порты добавлен admin-порт ядра 56002/tcp
  (его открывает deploy.sh): итого панель + 56000/56001/56002, 80/443 и SSH
  по-прежнему не трогаем.

## 1.9.3

Починка фоновых задач панели на старых systemd (Astra Linux 2.12, systemd 232):

- опция `systemd-run --collect` появилась только в systemd 235 — обновление
  панели, сертификат, Xray, каскад и WARP падали с
  `unrecognized option '--collect'`. Добавлен хелпер `run_transient_unit()`:
  при такой ошибке повторяет запуск без `--collect`;
- на современных системах поведение не изменилось (один вызов, с `--collect`).

## 1.9.2

Uninstall закрывает порты WDTT:

- `remove_firewall_rule()` принимает протокол (по умолчанию tcp): чистит ufw
  (циклом, т.к. могло накопиться несколько правил), firewalld и iptables
  по всем нашим комментариям (`WDTT_PANEL`, `WDTT_MANAGED`, `WDTT_MIRRORED`);
- `uninstall_panel()` закрывает порт панели (tcp) и порты ядра 56000/56001
  (tcp+udp);
- 80/443 осознанно не трогаем (могли открыть раньше для других служб),
  SSH-порт тоже не трогаем, чтобы не потерять доступ.

## 1.9.1

Починка автооткрытия портов на старых системах (Astra Linux / Debian 9):

- старый ufw 0.35 не знает ключевое слово `comment` — `ufw allow ... comment`
  молча падал (`|| true` съедал ошибку), поэтому 9999/tcp и 80/tcp оставались
  закрыты, а Let's Encrypt не выпускался. Добавлен хелпер `ufw_allow()`:
  пробует с комментарием, при неудаче — без него, в крайнем случае пишет WARN
  в лог вместо тишины;
- порты ядра (56000/udp+tcp, 56001/udp, admin/SSH) раньше писались только
  в raw-iptables, чего при активном ufw недостаточно. `deploy.sh` теперь
  при активном ufw регистрирует их и там (`ufw_allow_port`, с тем же
  fallback без `comment`).

## 1.9.0

Поддержка установки на Astra Linux (и других Debian-деривативов):

- `panel/install.sh` и `deploy.sh` ядра больше не падают с
  «Неподдерживаемый дистрибутив: astra»: добавлен явный `astra` в apt-семейство
  и общий fallback по `ID_LIKE` (debian/ubuntu → apt, rhel/fedora/centos → dnf/yum,
  arch → pacman);
- после установки пакетов проверяется версия Python: нужен 3.8+
  (панель использует dataclasses/f-строки). Только на Astra Linux со слишком
  старым Python (например, штатный 3.5 в 2.12) установщик сам собирает
  Python 3.9.22 из исходников (новейшая ветка под OpenSSL 1.1.0;
  3.10+ потеряла бы ssl-модуль) через `altinstall` + симлинки
  в `/usr/local/bin`, с повтором в один поток для слабых VM.
  На остальных дистрибутивах — понятная ошибка вместо позднего SyntaxError;
- юнит панели и admin-обёртка запускаются через вычисленный `PYTHON3_BIN`
  (`command -v python3`), а не хардкод `/usr/bin/python3` — иначе на Астре
  сервис стартовал бы на старом системном Python;
- в требованиях README упомянута Astra Linux.

## 1.8.3

Самообновление панели больше не жалуется на историю git, а перезаписывает дерево:

- `check` и `update` делают `git fetch --force --prune` с явным refspec
  `+refs/heads/*:refs/remotes/origin/*` — переживает force-push;
- fetch повторяется до 5 раз со sleep — закрывает гонку двух процессов
  (`cannot lock ref ... but expected ...`), из-за которой «Проверить обновления»
  показывало ошибку сразу после удачного обновления;
- `update` заменён с `merge --ff-only` / `pull` на `git reset --hard origin/ветка`:
  разошедшаяся история, локальные коммиты и правки в отслеживаемых файлах
  молча перезаписываются; неотслеживаемые файлы (userdata, бэкапы) не трогаем;
- тексты в карточке PANEL UPDATE и confirm-диалоге обновлены (reset --hard).

## 1.5.0

В диалогах создания/редактирования пользователя появилось поле «Количество устройств»
(лимит подключённых устройств на ключ, `max_devices`):

- одиночное создание и редактирование: поле `edit-max-devices` (1–10000, где 10000 —
  без ограничения); при редактировании подставляется текущее значение пользователя;
- массовое создание: поле `bulk-max-devices` задаёт лимит каждому создаваемому ключу;
- значение проверяется на бэкенде (`normalize_max_devices`): целое от 1 до `MAX_DEVICES`;

- `max_devices` теперь отдаётся в `UserView`, поэтому панель показывает реальный лимит
  при открытии карточки пользователя, а не только значение по умолчанию.

## 1.4.1

Веб-обновление панели больше не падает на грязном рабочем дереве репозитория:

- `update` в обёртке self-update сначала делает `git fetch`, затем `git merge --ff-only`
  в `origin/<ветка>`; при расхождении — обычный `git pull`;
- если слиянию мешают незакоммиченные правки в файлах, которые тоже изменились
  в origin, перезаписываются **только эти** файлы версией origin (`git checkout --`),
  а все прочие незакоммиченные изменения не трогаются;
- раньше при таких правках (например, `AGENTS.md`, `VERSIONS.md`) `git pull`
  прерывался с «Your local changes ... would be overwritten by merge», и кнопка
  «Обновить панель» выдавала «git pull не удался».

## 1.4.0

VK-хеши пользователей автоматически добиваются до четырёх из библиотеки панели:

- при создании пользователя (одиночном и массовом) недостающие хеши берутся из
  библиотеки `vk_hash_library` и дописываются в `passwords.json` — максимум 4,
  без дублей, с сохранением уже указанных;
- если хеши вообще не заданы, но библиотека не пуста, они подбираются целиком
  из библиотеки; если библиотека пуста — прежняя ошибка «Укажите хотя бы один
  VK-хеш»;
- для существующих пользователей добор выполняется один раз при старте панели
  (`users.fill_hashes`), идемпотентно и без перезаписи, когда добирать нечего;
- при обновлении `vk_hash` через `users.update` значение также добивается до 4;
- путь к базе панели берётся из `WDTT_PANEL_STATE` (по умолчанию
  `/var/lib/wdtt-panel/panel.db`), т.е. используется та же библиотека, что и в UI.

## 1.3.0

Возвращена кнопка обновления панели, но на новом принципе (git pull → установка
с сохранением конфига → полный перезапуск):

- в раздел «Система» возвращён блок «PANEL UPDATE» с текущей/доступной версией,
  кнопками «Проверить обновления» и «Обновить панель»;
- проверка и обновление идут через обёртку `/usr/local/sbin/wdtt-panel-self-update`,
  которая запускается вне systemd-песочницы панели (через `systemd-run`), поэтому
  `git`, запись в `/etc`, `/opt`, `/usr` и перезапуск служб ей доступны;
- проверка (`check`) делает `git fetch` в каталоге репозитория и пишет доступную
  версию в `/var/lib/wdtt-panel-private/self-update-status.json`;
- обновление (`update`) выполняет `git pull`, затем `install.sh update`
  (конфиг и данные сохраняются) и полный перезапуск панели, ядра WDTT и демонов;
- каталог репозитория запоминается при установке/обновлении в
  `/etc/wdtt-panel/source.conf` (`WDTT_REPO_DIR`); если репозиторий недоступен,
  панель показывает понятную ошибку;
- добавлены роуты `panel/version`, `panel/check`, `panel/update`, функции
  `panel_version()`, `schedule_panel_check()`, `start_panel_update()` и команда
  `install.sh restart` для перезапуска служб.

## 1.2.0

Установка поверх работающей панели теперь предлагает обновление:

- `sudo ./install.sh` при наличии установленной панели печатает текущую и
  целевую версии и спрашивает, обновить ли её (по умолчанию — да);
- при согласии запускается путь обновления: конфиг и данные сохраняются,
  панель переводится на новую версию без потери пароля, URL-пути и сертификатов;
- перед миграцией `panel/install.sh update` создаёт снимок `config.json` в
  `/var/lib/wdtt-panel-private/config-backups/` (хранятся 20 последних) и
  снимок базы WDTT;
- конфиг переносится на новую версию: недостающие поля досыпаются значениями
  по умолчанию, порты нормализуются, поле `version` обновляется;
- `--force-clean` по-прежнему сносит установку и ставит начисто,
  `--non-interactive` обновляет панель без вопросов.

## 1.0.0

Первый релиз под новым версионированием. Что вошло в форк к этому моменту:

- панель всегда работает от root и вызывает root-хелпер напрямую: юнит задаёт

### Установщик (`panel/install.sh`)

- добавлен режим локального ядра `WDTT_SOURCE_DIR` (по умолчанию `src/proxy-turn-vk-android-1.4.3`):

- при установке форк ядра копируется в `/opt/wdtt-panel/src`, чтобы последующие
  обновления из `/opt` тоже не обращались к GitHub.

## Как проверить, что лимиты сняты

```bash
grep maxGeneratedPasswords /opt/wdtt-panel/src/proxy-turn-vk-android-1.4.3/server/database_bot.go
# maxGeneratedPasswords = 10000
grep MAX_USERS /opt/wdtt-panel/wdtt_panel/core.py
# MAX_USERS = 10000
```

На работающем сервере: команда `/list` в Telegram-боте покажет «Активно: N/10000»,
а панель в разделе Пользователи — счётчик «N / 10000».
